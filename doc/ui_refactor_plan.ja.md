# UIリファクター方針

## 前提

- Python / PySide6 / Windows venv セットアップを維持する。
- ユーザーは `run_gui.bat` から起動し、追加の開発環境を用意しない。
- アプリ本体の MIT License を維持する。
- 既存のCLI処理 (`extract_frames.py`, `yolo_mask.py`, `stitch_mask.py` など) はGUIから呼び出す構成を維持する。

## 画面構成

タブUIはやめ、次の構成を標準とする。

- 上部: アプリ名、シーンフォルダ
- 左: ワークフローナビゲーション
- 中央: 現在の作業画面
- 下: 進捗、ログ、実行/キャンセル

これにより、現在どの工程にいるか、どのシーンを操作しているか、処理が動いているかを常に見える状態にする。

## 共通部品

数値入力は、調整しながら結果を見る用途では `DragSpinBox` / `DragDoubleSpinBox` を使う。

- 横ドラッグで調整できる
- `Shift` で細かく、`Ctrl` で大きく調整できる
- 値域、刻み、小数桁、単位表示を呼び出し側で指定できる
- 危険な値域はGUI側でも制限する

パス入力、折りたたみ、プレビュー、実行状態、ログ表示は共通部品として扱い、各Stepが個別に似たUIを再実装しないようにする。

## 検証

`QT_QPA_PLATFORM=offscreen` では、この環境のQtフォントDBが空になり、スクリーンショットの文字が四角表示になる。そのため、見た目確認には使わない。

UIの見た目確認は通常のWindows GUIプラットフォームで短時間だけ実アプリを描画し、`QWidget.grab()` でスクリーンショットを保存して行う。

自動テストは引き続き `pytest` を使う。GUI部品の値域やコマンド生成は offscreen smoke test で確認する。
