# STechDrive 3DGS Utils Step 3 — マスク生成GUI

## 概要

STechDrive 3DGS Utils の Step 3 は、以下のマスク処理をまとめて実行する PySide6 GUI です。

- `yolo_mask.py`（人物マスク生成）
- `sky_mask.py`（Mask2Former ADE20K 空マスク生成）
- `stitch_mask.py`（スティッチ領域マスク付与）
- `overexposure_mask.py`（白飛びマスク付与）
- `custom_mask.py`（ユーザー指定マスクの合成）

抽出済みフレーム、または外部から用意した連番画像（`images/`）からマスク（`masks/`）を作る用途を想定しています。

## 起動

```bat
run_gui.bat --scene ./scene01
```

## 主な入力項目

- `シーンフォルダ`:
  - ベースフォルダ。Step 3 では `images` / `masks` が自動入力されます。
- `画像フォルダ`:
  - `yolo_mask.py` の入力画像フォルダ。
- `マスクフォルダ`:
  - `yolo_mask.py` の出力先。
  - `stitch_mask.py` 実行時は入力/出力の両方として使います。
- `画像タイプ`:
  - `360°`: エクイレクタングラー360°画像。スティッチ境界マスクと360°底面再検出を使えます。
  - `通常`: 普通の動画フレームやデジタル一眼の連番画像。スティッチ境界マスクと360°底面再検出は無効になります。
- 設定タブ:
  - `YOLO`: YOLO/SAMの検出強度、拡張量、下部検出強化、検出クラスを設定します。
  - `スティッチ/白飛び`: スティッチ境界マスクと白飛びマスクの設定をまとめています。
  - `空`: Mask2Formerによる空検出設定をまとめています。
  - `カスタムマスク`: ユーザー指定PNGマスクの読み込みと解除を行います。
- `YOLO Level`:
  - `yolo_mask.py --level`（0〜3）
  - 360°画像では `2 高品質` から始めるのを推奨します。
  - 処理時間を優先する確認用は `1 標準`、それでも人物が漏れる場合は `3 最高` を使います。
  - 通常画像では `1 標準` から始めます。
- `YOLO Expand (px)`:
  - `yolo_mask.py --expand`
  - 既定は `2px`。固定ピクセル数を横ドラッグで調整できます。
  - 安全のため、GUIでは `-16〜32px` に制限されます。
- `下部検出強化`:
  - エクイレクタングラー360°画像の真下付近の漏れを減らすプリセットです。
  - `標準`: 下部が十分にマスクされている素材向け。床や地面の余計なマスクを増やしにくい設定です。
  - `高`: 真上から見た撮影者、三脚、手元が下部に残る素材向け。まずはこちらを試します。
  - `最高`: `高` でも下部に人物が残る場合のみ使います。より重く、床や地面を余分にマスクしやすくなります。
  - `画像タイプ=通常` では使いません。
- `YOLO Classes`:
  - 通常は折りたたみ表示。展開するとクラスをチェックで選択できます。
  - 数値IDを覚えなくても `id: 名前` で選択可能です。
  - 既定は `person`（`id=0`）のみ。
  - `yolo_mask.py --classes` に渡されます。
- `境界マスク幅 (度)`:
  - `stitch_mask.py --boundary-width`
  - `画像タイプ=通常` では使いません。
- `Stitch Workers`:
  - `stitch_mask.py --workers`
  - 数値欄は横ドラッグで調整できます。
- `カスタムマスク`:
  - ユーザーが用意した静的マスク画像を、最後に `masks/` の各マスクへ AND 合成します。
  - 入力はPNGのみです。8bit/16bitのグレースケール、RGB、RGBAを受け付け、RGB/RGBAはグレースケール化します。アルファは無視します。
  - 8bitは128以上、16bitは32768以上を白として0/255へ二値化します。白=採用、黒=除外の規約です。
  - カスタムマスクの縦横ピクセル数が元画像と一致する画像にだけ適用されます。不一致の場合は自動リサイズせず、その画像をスキップします。
  - 全画像がサイズ不一致で1枚も適用できなかった場合は、カスタム工程を失敗扱いにします。
  - `カスタム` をONにした時点で未選択なら、ファイル選択ダイアログが開きます。読み込みボタンから先に選ぶこともできます。
- `YOLO/SAMプレビュー`:
  - 現在プレビューに表示している1枚だけに `yolo_mask.py` を実行します。
  - 初回のYOLO/SAM実行時に、第三者モデル/ライセンスの確認ダイアログが表示されます。モデル重みはアプリに同梱されておらず、ユーザー環境へダウンロードされる場合があります。
  - 結果は赤いオーバーレイとして表示され、`masks/` には保存されません。
  - `画像タイプ` / `YOLO Level` / `YOLO Expand` / `下部検出強化` / `YOLO Classes` の現在値を使います。
  - 全フレームのマスクを書き出す場合は、下部の `生成` を実行します。
- `表示中を再処理`:
  - 現在プレビューに表示している1枚だけ、現在の設定でマスクを作り直して `masks/` に保存します。
  - `YOLO` や `空` がONなら単一画像に対応するモデル処理を再実行し、`スティッチ` / `白飛び` / `カスタム` がONなら同じ1枚に続けて合成します。
  - 全体を再生成せず、プレビューで見つけた検出漏れだけを設定変更して直す用途です。
- `マスクプレビュー`:
  - 見出し右端のアイコンで、1枚プレビューとサムネイル一覧を切り替えます。
  - サムネイル一覧では既存マスクを赤いオーバーレイで確認できます。マスク表示アイコンで、サムネイルを再構築せずにオーバーレイの表示/非表示を切り替えられます。
  - ダブルクリックすると、その画像を表示した状態で1枚プレビューへ戻ります。
  - `Ctrl` クリック、`Ctrl+Shift` クリック、`Shift` クリックでWindows Explorerと同じ感覚の複数選択ができます。
  - サムネイル一覧へ切り替えると一覧にフォーカスが移るため、矢印キーは見えているサムネイル選択の移動として動作します。
  - サムネイル一覧で複数選択した状態の `選択中を再処理` は、選択画像だけを現在のマスク生成設定で `masks/` に再生成します。
  - ステータスは1行で省略表示され、全文はツールチップで確認できます。
  - サムネイルは遅延生成され、表示中の行を優先し、ステップ切り替え後も使えるキャッシュを再利用します。大量画像でも毎回全量を作り直さない設計です。

## 各値の意味と調整指針

### `YOLO Level`（360°デフォルト: `2`、通常画像デフォルト: `1`）

- 何を制御するか:
  - 人物検出の探索強度です。値が大きいほど追加の局所処理が増え、検出漏れに強くなります。
- 値を上げると:
  - 検出は強くなる傾向
  - 処理時間とVRAM使用量は増加
- 目安:
  - `0`: 最速だが漏れやすい
  - `1`: 速度と精度のバランス。通常画像の開始点
  - `2`: 360°画像の推奨開始点
  - `3`: `2` でも人物が漏れる場合のみ。重い

### `YOLO Expand (px)`（GUIデフォルト: `2`）

- 何を制御するか:
  - SAM後の人物マスク境界を何ピクセル膨張/収縮させるか
- 符号の意味:
  - 正の値: 膨張（人物周辺を広めに黒くする）
  - 負の値: 収縮（人物領域を細くする）
  - `0`: 形状変更なし
- 値を上げると:
  - 人物の取り残しは減るが、背景を巻き込みやすくなる
- GUI操作:
  - 数値欄は横ドラッグで調整できます。
  - 安全のため、GUIでは `-16〜32px` に制限されます。

### `下部検出強化`（GUIデフォルト: `標準`）

- 何を制御するか:
  - 360°画像の真下付近に写る撮影者、三脚、手元の検出漏れを減らします。通常画像には影響しません。
- `標準`:
  - 通常の360°素材向け。下部がすでに十分マスクされている場合に使います。
- `高`:
  - 真上から見た撮影者など、通常の人物形状から外れたケース向けです。
- `最高`:
  - `高` でも下部に人物が残る場合のみ使います。
  - 初回は追加モデルのダウンロードが発生する場合があります。
- 注意:
  - 強くするほど処理時間は増え、床や地面を余分にマスクする場合があります。

### `境界マスク幅 (度)`（デフォルト: `5.0`）

- 何を制御するか:
  - 除外するスティッチ境界帯の合計幅（度）。`5.0` は従来の `FOV=175` と同等です。
- 値を上げると:
  - マスクされるスティッチ境界領域が広がる（保守的）
- 値を下げると:
  - マスク領域が狭まる。`0` はほぼ無効です。
- GUI操作:
  - 数値欄は横ドラッグで調整できます。
  - 安全のため、GUIでは `0.0〜30.0` 度に制限されます。
- 注意:
  - 撮影時に手ブレ補正や水平補正を強くかけた素材では、幾何がずれて想定どおりに効かない場合があります。
  - GUIのマスクプレビューで、抽出フレーム上の赤い範囲を確認しながら調整してください。

### `Stitch Workers`（デフォルト: `CPUコア数`）

- 何を制御するか:
  - `stitch_mask.py` の並列プロセス数
- 値を上げると:
  - 速くなる可能性はあるが、CPU使用率が高くなりPC操作性は下がる
- 実用目安:
  - 作業しながら回すなら `コア数-2` 程度
  - バッチ処理専用なら `コア数` でも可

### `空` タブ

- 何を制御するか:
  - `sky_mask.py` に渡すMask2Former ADE20K空検出設定。
- 既定:
  - `方式=高品質`。360°画像では直処理と上部投影ビューを合成します。
- 調整の目安:
  - 境界をもう少し安定させたい場合は `推論サイズ` を上げます。
  - 誤検出が多い場合は `最小スコア` を上げるか、`空拡張` を負値にします。
  - 小さな誤検出は `小領域除去` と `上端につながる空だけ` で抑えます。

## デフォルト値は妥当か？

結論として、現状デフォルトは「まず動かす」用途として妥当です。

- `YOLO Level=2`:
  - 360°画像では人物検出の初期値として適切
- `YOLO Expand=2`:
  - SAM後の境界補正として控えめで、人物周辺の背景を削りすぎにくい
- `境界マスク幅=5`:
  - 従来の `FOV=175` 相当の無難な値
- `Workers=CPUコア数`:
  - 最速寄り。重い場合は手動で下げればよい
- `空: 方式=高品質 / 推論サイズ=768`:
  - 精度優先の初期値。空マスクを使う場合は、まずこの設定で確認します。

## 8Kフレーム（7680x3840）での実務プリセット

まずは次の値から開始するのを推奨します。

- `YOLO Level=2`
- `YOLO Expand=2`
- `境界マスク幅=5`
- `Stitch Workers=コア数-2`（操作しながら実行する場合）

仕上がりを見て調整:

- 人物マスク漏れが目立つ: `Level 2 -> 3`、または `Expand 2 -> 4~6`
- 下部の撮影者だけ漏れる: `下部検出強化 標準 -> 高`。それでも足りない場合は `最高`
- 背景を削りすぎる: `Expand 2 -> 0~1`
- スティッチ境界の破綻が残る: `境界マスク幅 5 -> 8~10`
- マスクしすぎる: `境界マスク幅 5 -> 2~3`

## 実行

`マスク` で `YOLO` / `スティッチ` / `白飛び` / `空` / `カスタム` を選び、`生成` を押します。
複数選択時は `YOLO -> スティッチ -> 白飛び -> 空 -> カスタム` の順に実行されます。

`selected_frames.csv` がない場合でも、シーンフォルダ内の `images/` に画像があれば外部画像として生成できます。
この場合、Step 2 の採用/除外チェックは行われません。

## 補足

- GUIは内部でCLIスクリプトをそのままサブプロセス実行するため、挙動はCLIと一致します。
- YOLO/SAMおよび空マスク機能では、別ライセンスの第三者ライブラリおよびモデル重みを使用します。詳細は [../THIRD_PARTY_LICENSES.md](../THIRD_PARTY_LICENSES.md) を参照してください。
- 実行ログは下部ログパネルで確認できます。
