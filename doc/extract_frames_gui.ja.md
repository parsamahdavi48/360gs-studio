# extract_frames_gui.py パラメータ解説（日本語）

このドキュメントは `Frame Extractor` GUI の各項目が何を制御しているかを、単位と挙動まで含めて説明します。
特に `Change Threshold` を中心に、`8K (7680x3840) / 30fps` 動画での解釈を具体化しています。

## 前提

- `Run Extraction` は「解析」と「実画像書き出し」が別です。
- 解析は `Analysis Width` で縮小したグレースケールで行います。
- 実際に `images/` に保存される画像は、元動画解像度のままです。

## GUI項目（数値系）

### `Fixed Interval (sec)`

- 単位: 秒
- 使われるモード: `Fixed Interval` のときのみ
- 意味: 何秒ごとに1枚抜くか
- 内部計算: `step = round(interval_sec * fps)` フレームごとに選択
- 30fps換算例:
  - `0.5` 秒 = 約15フレームごと
  - `1.0` 秒 = 約30フレームごと
- 値を上げる: 枚数が減る
- 値を下げる: 枚数が増える

### `Change Threshold`

- 単位: 無次元（0.0〜1.0）
- 使われるモード: `Change-Based` のとき
- 意味: 前フレームとの差分がこの値以上なら「変化あり」とみなして抽出候補にする
- 内部スコア定義:
  - `change_score = mean(abs(gray_t - gray_(t-1))) / 255`
  - `gray` は `Analysis Width` で縮小したグレースケール画像
- `0.04` の意味:
  - 平均画素差が `0.04 * 255 = 10.2` 階調程度
- 値を上げる:
  - 変化判定が厳しくなり、抽出枚数は減る傾向
- 値を下げる:
  - 小さな動きでも拾いやすくなり、抽出枚数は増える傾向

### `Min Gap (sec)`

- 単位: 秒
- 使われるモード: `Change-Based`
- 意味: 直前に選んだフレームから、この秒数ぶんは次を選ばない（最短間隔）
- 内部計算: `min_gap_frames = round(min_gap_sec * fps)`
- 30fps換算例:
  - `0.25` 秒 = 約8フレーム
- 値を上げる:
  - 最短間隔が広がるため、枚数が減る
- 値を下げる:
  - 近いフレームを拾えるため、枚数が増える

### `Max Gap (sec)`

- 単位: 秒
- 使われるモード: `Change-Based`
- 意味: 変化が小さくても、この秒数を超えたら強制的に1枚選ぶ（最長間隔）
- 内部計算: `max_gap_frames = round(max_gap_sec * fps)`
- 30fps換算例:
  - `2.0` 秒 = 約60フレーム
- 値を上げる:
  - 強制抽出が減るため、枚数が減る傾向
- 値を下げる:
  - 強制抽出が増えるため、枚数が増える傾向

### `Analysis Width`

- 単位: ピクセル
- 意味: 変化量判定とブラー判定を行う解析解像度の横幅
- 重要:
  - 解析専用の解像度
  - 出力画像解像度（`images/`）は変わらない
- 8K動画での解釈:
  - 元 `7680x3840`、`Analysis Width=960` なら解析は `960x480`
  - ほぼ「横1/8、縦1/8」相当の情報で差分判定
- 値を上げる:
  - 微細な変化に敏感になる傾向
  - 解析時間は長くなる
- 値を下げる:
  - ノイズに強くなる場合がある
  - ただし細かい変化は見落としやすくなる
  - 解析は速くなる

### `Blur Percentile`

- 単位: パーセンタイル（0〜100）
- 意味:
  - 選ばれたフレーム群のブラー指標（Laplacian分散）に対してしきい値を作る
  - しきい値未満のフレームを「置換候補」にする
- 例:
  - `25.0` なら下位25%を候補化
- 値を上げる:
  - 置換候補が増える（積極的）
- 値を下げる:
  - 置換候補が減る（保守的）

### `Blur Window (frames)`

- 単位: フレーム数
- 意味: ブラー置換時に前後何フレームまで探索するか（±window）
- `0` の意味: 自動設定
- 自動設定式:
  - `max(1, min(round(0.35*fps), 12, round(0.6*min_gap_frames)))`
- 30fps・`min_gap=0.25s(=8f)` の例:
  - `round(0.35*30)=11`
  - `round(0.6*8)=5`
  - 自動値は `5`
- 値を上げる:
  - 置換先が見つかりやすくなる
  - ただし時間的に離れたフレームへ置換しやすくなる
- 値を下げる:
  - 近傍だけで置換するため保守的

### `JPEG Quality (ffmpeg -q:v)`

- 単位: ffmpegの`qscale`（実質的に整数）
- 意味: JPEG書き出し品質
- 重要: 数値が小さいほど高画質・大容量
- 例:
  - `2` は高画質（デフォルト）
- 値を上げる:
  - 画質低下、ファイルサイズ減
- 値を下げる:
  - 画質向上、ファイルサイズ増

## GUI項目（補助）

### `Filename Prefix`

- 空欄時: 入力動画ファイル名を自動使用
  - 例: `mikan2.mp4` -> `mikan2_000123.jpg`
- 指定時: その文字列をプレフィックスとして使用
- `Export Target Folder=images` の in-place finalize 時も同じプレフィックス体系で連番化

### `Estimated Output`（Instant / Sampled）

- `Instant`:
  - すぐ出る概算
  - `duration/max_gap`〜`duration/min_gap` の理論範囲を表示
- `Sampled`:
  - バックグラウンド解析による見積り
  - `Change-Based` 用

## 8K / 30fps でのデフォルト値の読み方

デフォルト:

- `Change Threshold=0.04`
- `Min Gap=0.25s`（約8f）
- `Max Gap=2.0s`（約60f）
- `Analysis Width=960`（8Kなら `960x480` 解析）

このとき抽出間隔は概念的に:

- 最短 約0.25秒
- 最長 約2.0秒

なので理論上の抽出レートは:

- 約 `0.5〜4.0` 枚/秒（シーン変化に依存）

例として、`14621f / 30fps ≒ 487.4秒` の動画なら、

- 理論最小: `ceil(487.4 / 2.0) = 244` 枚
- 理論最大: `ceil(487.4 / 0.25) = 1950` 枚

実際の出力枚数は `Change Threshold` と被写体運動でこの範囲内に収まります。

## 調整の実務ガイド（徒歩撮影）

- 枚数が多すぎる:
  - `Change Threshold` を上げる（例 `0.04 -> 0.05`）
  - `Min Gap` を上げる（例 `0.25 -> 0.35`）
  - `Analysis Width` を下げる（例 `960 -> 720`）
- 枚数が少なすぎる:
  - `Change Threshold` を下げる（例 `0.04 -> 0.03`）
  - `Max Gap` を下げる（例 `2.0 -> 1.5`）
- ぶれ置換が弱い:
  - `Blur Percentile` を上げる（例 `25 -> 35`）
  - `Blur Window` を少し増やす（例 `0(自動) -> 8`）

まずはデフォルトで1本回し、`selected_frames.csv` の `status`（`ok/replaced/fallback_keep`）を見て調整するのが安全です。
